## Step 0：GLB 导入后全局初始化检查（必须对所有 GLB 一视同仁）

### 0.1 目的
不同资产的坐标系、尺度、原点、朝向都可能乱七八糟。若不统一处理，后续的“进室内 / 找地面 / 连续移动”全都会变成玄学。
必须先执行 scene stats pass（可不渲染），扫描 `/Users/sota/code/3d_new/data/scenes/3d-assets` 得到数据分布，再做后续初始化策略。

scene stats pass 产物：
- `scene_stats.json`
  - `max_dim` 分布（`min/median/p95`）
  - `aabb_volume` 分布（`min/median/p95`）
  - 异常场景识别（例如 `max_dim < 1m` 或 `max_dim > 200m`）

### 0.2 必做的初始化动作（对每个导入 GLB 都执行）
- **AABB 计算（世界坐标）**
  - 获取场景的 Axis-Aligned Bounding Box：`center`, `size`
- **尺度归一（可选但强烈建议）**
  - 让场景最长边落在一个合理范围（例如 10~50m 级别，具体看你的数据分布）
- **平移到原点**
  - `scene_translation = -AABB.center`，让中心对齐到 `(0,0,0)`
- **高度基线对齐（可选）**
  - 让 AABB 的 `min_y` 对齐到 0（或你定义的“地面附近”高度）

### 0.3 Step 0 的验收标准（Fail-fast）
- [ ] 导入后能稳定拿到 `AABB.center/size`
- [ ] `size` 不出现极端异常（比如全 0、或大到离谱）
- [ ] 执行平移/缩放后，场景仍可渲染、无崩坏
- [ ] 任意一次导入，初始化输出都有日志（scene_id / scale / translation）
> 产物建议：`scene_init.json`（每个 scene 一份），记录 scale、translation、AABB 等，用于复现与排查。

### 0.4 Navmesh 失败必须显式状态化（禁止 silent fail）
必须输出并落盘：
- `navmesh_status = OK | RECOMPUTED_OK | FAIL`
- `navmesh_fail_reason`（从异常和日志关键字归类）
- `fallback_used = none | relaxed_navmesh | no_navmesh_sampling`

并写入 `scene_init.json`（必要时同步到 `traj_meta.json`）用于统计失败分布。

### 0.5 Navmesh 策略：检测 → 多级修复 → 兜底
1. 优先加载已有 navmesh（若存在缓存）：
   - 先检查 `pathfinder.is_loaded`
   - 命中缓存则直接加载，避免重复构建
2. 未命中或加载失败则重建，并采用分级重试（从严格到宽松）：
   - Attempt A：默认参数（`NavMeshSettings().set_defaults()`）
   - Attempt B：增大 voxel/cell（更粗网格），适当降低 agent 半径/高度
   - Attempt C：进一步放宽可行走参数（如 climb/slope，取决于可调字段）
3. 每次重试后都必须做有效性检查：
   - `pathfinder.is_loaded == True`
   - `get_random_navigable_point()` 返回可用点

### 0.6 Step 0 输出新增字段（用于后续分支执行）
- `navmesh_status`
- `navmesh_attempts = [{attempt_id, settings_summary, success, error}]`
  - `settings_summary` 至少包含：
    - `agent_radius`
    - `agent_height`
    - `cell_size` / `voxel_size`（按 Habitat API 可用字段落盘）
    - `attempt_wall_time_ms`
    - `navmesh_poly_count`（如果可获取，否则写 `null`）
- `fallback_plan = navmesh | no_navmesh_sampling`
- `scene_init_ok` 与失败原因（fail-fast 时必须可追溯）
- `debug_cam_pose`（固定可复现的 debug 相机位姿：`position/rotation/fov`）

### 0.7 Debug 渲染可比对要求
Step 0 的 debug RGB/Depth 需要可跨场景对齐比较：
- debug 相机位姿必须由 AABB 规则确定，禁止随机位姿
- 相机参数（分辨率/FOV）固定
- `debug_cam_pose` 必须写入 `scene_init.json`

### 0.8 常见 navmesh 失败根因（用于日志归类）
- 场景尺度异常（超大/超小）
- mesh 非闭合、碎片化或自交
- agent 参数不合适（半径/高度导致不可走）
- 缺少可碰撞几何（只有 render mesh）
- 坐标轴/up-axis 混乱导致“地面”推断错误

## Step 1：先“进入室内”——否则数据没价值

### 1.1 前置依赖（必须）
Step 1 只能消费 Step 0 已完成且可追溯的初始化结果：
- `scene_init_ok == true`
- `quarantine == false`
- 使用 Step 0 落盘的 `post_scene_source`（优先）或 `scene_path`
- 读取 Step 0 的 `navmesh_status/fallback_plan/debug_cam_pose/sensor_config` 作为启动参考

> 原则：Step 1 不是重新导入场景，而是在 Step 0 统一坐标和尺度之后做“可用起点搜索”。

### 1.2 室内判定升级：硬门 + 打分（不依赖语义）
对每个候选位姿渲染深度后，计算 6 个廉价特征：
- `r_valid`: 深度有效像素比例（默认 `isfinite(depth) && depth > znear`；不建议用固定 `depth_valid_max_m` 作为 validity gate）
- `r_near`: 近距离占比（`depth < D_near`）
- `r_far`: 远距离占比（`depth > D_far`）
- `r_edge`: 深度边缘占比（Sobel/Canny，建议在 depth 上做）
- `d05`: 深度 5% 分位数（替代 `min(depth)`，更抗噪）
- `depth_iqr`: 深度 IQR（`p75-p25`，衡量结构层次）

硬门（Gate）：
- `r_valid > T_valid`（建议 0.6~0.7）
- `d05 > T_wall`（建议 0.15~0.25m，过滤贴墙/贴脸）

软评分（Score）：
- `S = w1*r_near + w2*(1-r_far) + w3*r_edge + w4*norm(depth_iqr)`
- `norm(depth_iqr)` 建议做裁剪归一化，避免被极端值污染
- 启动点选择采用 top-K（不要“第一个过线就停”）

> 说明：`depth_valid_max_m` 可以保留为可选兼容开关（仅在特殊数据集启用），默认应关闭；空旷惩罚由 `r_far` 和 `score` 完成。

### 1.3 进入室内策略：1-step lookahead 局部贪心
每次仅在小动作集合中选下一步：
- `turn_left_small`
- `turn_right_small`
- `forward_small`
- `forward_medium`
- `back_small`（防贴墙死锁）

动作选择：
- 对每个动作做 1 步试探渲染（低分辨率 depth 即可）
- 计算试探后的 `S`
- 选 `S` 最大的动作执行

停止条件：
- 达到 `S >= S_min` 且通过 Gate
- 或达到 `max_actions_per_start` 后切换起点

### 1.4 No-Navmesh 启动：三关筛选（必须可运行）
当 `navmesh_status == FAIL` 或 `fallback_plan == no_navmesh_sampling`：
- 关 1（落地可靠性）：
  - 在 AABB 采样 `(x,z)`，从高处向下 raycast 得 `p_floor`
  - 要求 `dot(hit_normal, up) > 0.8`，避免命中墙面
- 关 2（局部 clearance）：
  - 在相机高度做四向短射线（0.3~0.5m）
  - 任意方向过近命中则 reject
- 关 2.5（可选，向前命中）：
  - 沿候选 yaw 方向发短射线（2~5m，允许多次 yaw 试探）
  - 全 miss 或命中过远则 reject（典型失败码：`REJ_FORWARD_MISS/REJ_FORWARD_TOO_FAR`）
- 关 3（室内评分）：
  - 对候选点 + yaw 计算 Gate + `S`
  - 选 top-K 进入动作搜索

退出上限（防卡死）：
- `max_start_samples`（建议 200）
- `max_no_nav_candidates`（建议 100~300）

### 1.5 Step 1 输出（结构化失败，便于调参）
每个 scene 产出 `step1_start_report.json`（或并入 `traj_meta`）：
- `start_candidates_total`
- `accepted_candidates`
- `best_score`
- `best_metrics = {r_valid, r_near, r_far, r_edge, d05, depth_iqr}`
- `chosen_start_pose`（position/rotation/yaw）
- `planner_trace`（动作序列、每步分数）
- `reject_histogram`：
  - `REJ_INVALID_DEPTH`
  - `REJ_TOO_CLOSE_WALL`
  - `REJ_TOO_OPEN`
  - `REJ_LOW_TEXTURE`
  - `REJ_SCORE_LOW`
  - `REJ_NO_FLOOR_HIT`
  - `REJ_CLEARANCE_FAIL`
  - `REJ_FORWARD_MISS`
  - `REJ_FORWARD_TOO_FAR`

### 1.6 Step 1 验收标准（避免“勉强室内”）
- [ ] 90%+ scene 的起始帧通过 Gate 且 `S >= S_min`
- [ ] 起始帧满足质量下限：`d05 > 0.2m`、`r_valid > 0.7`
- [ ] 不出现大比例黑帧/空白帧/贴墙帧
- [ ] 所有失败 scene 均有结构化 `reject_histogram` 与 `fail_reason`

> 原则：Step 1 目标不是“找到一个能动的位置”，而是“找到可持续产出高质量轨迹的启动位姿”。

## Step 2：Floor（确定“地面”）——高度、连续移动、质量过滤的共同地基

> 目标：在 **不依赖语义、不依赖 navmesh** 的前提下，为每个可用帧稳定输出 `floor_plane / floor_normal / floor_height`，并给出明确的 `floor_status` 与 `fail_reason`。  
> 推荐策略：**RANSAC 平面拟合为主**；失败时进入 **Ray-way（射线兜底）**；两者都失败则 fail-fast（或跳帧）。

### 2.0 关键定义（强制统一）
- `up = +Y`（若引擎或资产不是 +Y up，必须在 Step 0 中完成统一并落盘）
- `floor_plane = (n_x, n_y, n_z, d)`（世界坐标系，满足 `n·x + d = 0`，且 `||n|| = 1`）
- `floor_normal = n`（方向统一为与 `up` 同向）
- 朝向统一规则：若拟合后 `dot(n, up) < 0`，必须执行 `n=-n, d=-d`；此后高度相关量统一按该朝向计算
- `floor_height` 统一定义（当 `up=(0,1,0)`）：`floor_height = -d / n_y`（需 `n_y > 0`）；等价于平面与“过原点的世界 up 轴直线”的交点高度
- `cam_height_above_floor = n·p_cam + d`（有符号垂距，期望为正；验收区间内）

### 2.1 Step 2 输入 / 输出（落盘字段）
**前置依赖（必须来自前序步骤）**
- Step 0：`scene_init_ok = true`，且 up-axis 已统一为 `+Y`
- Step 1：`step1_ok = true` 且 `accepted_pose` 可用（Step 2 只在该 pose 上估计 floor）

**输入（每帧 / 每个候选 pose）**
- `depth`（必须）
- `K`（相机内参；或由 FOV + 分辨率重建）
- `T_wc`（相机到世界变换；必须明确方向）
- `rgb`（可选，仅用于 debug）

**输出（写入 `frame_meta.jsonl` 或 `poses.jsonl`）**
- `floor_status = OK | FALLBACK_OK | FAIL`
  - 可选扩展（2.7 启用时）：`SLOPE_OK`
- `floor_method = ransac | ray_fallback | ray_fallback_depth_proxy | ransac_forced(debug) | none`
- `floor_plane = [nx, ny, nz, d]`
  - 约定：`floor_plane` 表示当前帧最终用于下游的平面（由 `floor_used` 决定）
- `floor_normal = [nx, ny, nz]`
- `floor_height`
- `cam_height_above_floor`
- `valid_points_in_roi` / `sampled_points`
- `inlier_ratio`（RANSAC 路径）
- `plane_residual_p50` / `plane_residual_p95`（RANSAC 路径）
- `ray_grid` / `ray_offset_m`（Ray 路径采样拓扑与尺度）
- `ray_hit_count` / `ray_hit_height_median` / `ray_hit_height_mad`（Ray 路径）
- `ray_preflight`（Ray-way 自检结果：是否可用、首个 hit 距离、失败原因）
- `floor_plane_raw` / `floor_plane_smooth` / `floor_used = raw | smooth`
- `ransac_low_height_quantile_used` / `ransac_attempts`（低高度切片重试记录）
- `floor_init_lookdown_applied` / `floor_init_lookdown_delta_y_m`
- `cam_y_before_floor_adjust` / `cam_y_after_floor_adjust` / `cam_y_delta_floor_adjust`
- `cam_y_minus_floor_height`（用于核对 `cam_height_above_floor` 与应用链路）
- `floor_pose_apply_applied` / `floor_pose_apply_reason`
- `floor_pose_apply_rgb_l1_diff`（before/after RGB 的 L1 差）
- `floor_pose_apply_readback_before` / `floor_pose_apply_readback_after`（相机位姿读回）
- `run_state = DONE | FAIL | TIMEOUT`（批量执行可解释状态）
- `progress_marker`（最后执行到的阶段，如 `render_before_done`）
- `timeout_stage`（超时时记录；无信息时写 `unknown_or_pre_step2`）
- `stage_timing_sec`（`t_load_scene / t_render_before / t_floor_estimate / t_apply_pose / t_render_after / t_write_artifacts`）
- `floor_confidence`（0~1，便于下游筛帧）
- `fail_reason`（失败必填）
- `fail_reason_detail`（建议必填，记录判失败时的关键数值与阈值）

推荐 `fail_reason` 枚举（至少覆盖）：
- `insufficient_depth_points`
- `ransac_no_plane`
- `normal_not_up`
- `camera_height_out_of_range`
- `residual_too_large`
- `ray_no_hit`
- `ray_height_unstable`

`floor_confidence` 默认建议（可直接落地）：
- `clamp01(x) = min(1, max(0, x))`
- RANSAC 路径：
  - `floor_confidence = clamp01(w1*inlier_ratio + w2*(1 - plane_residual_p95/max_residual) + w3*(1 - |cam_height_above_floor - h_mid|/h_span))`
  - 建议默认：`w1=0.4, w2=0.4, w3=0.2, h_mid=1.5, h_span=0.7`
- Ray 路径：
  - `floor_confidence = clamp01(w1*(ray_hit_count/ray_expected_hits) + w2*(1 - ray_hit_height_mad/0.05))`
  - 建议默认：`w1=0.6, w2=0.4, ray_expected_hits=9`（`3x3`）或 `5`（`cross5`）

### 2.2 主路径：RANSAC 平面拟合（Primary）
1. ROI 采样（默认取图像高度 `60%~95%`，并过滤无效深度）
2. 点采样预算控制（复杂度与稳定性必须可控）：
   - `max_points` 建议 `5000~20000`（随机或网格下采样）
   - `min_points` 建议 `500`（低于阈值直接 `insufficient_depth_points`）
3. 反投影到 camera 点云，再通过 `T_wc` 转到 world 点云
4. **低高度切片后再拟合**（避免墙面/台面主导）：
   - 先按 world `y` 取低分位点：`q ∈ {0.20, 0.35, 0.50}`（可配）
   - 在切片点上做 RANSAC；若失败则自动扩大分位重试
   - 可选终止兜底：`q=1.00`（全 ROI，防止“点数不足导致永远不跑”）
5. RANSAC 拟合平面，得到 `n, d` 与内点集合，并保证 `n` 归一化且与 `up` 同向
6. 度量定义（强制统一）：
   - `inlier_ratio = (#inliers) / (#points_in_current_low_height_slice)`
   - `residual = |n·x + d|`（点到平面的正交距离；`n` 归一化后单位为米）
7. 几何过滤（不满足任一项即判本次切片尝试失败）：
   - `dot(n, up) > 0.9`
   - `inlier_ratio >= min_inlier_ratio`（建议起始值 `0.15`）
   - `cam_height_above_floor ∈ [0.8m, 2.2m]`
   - `plane_residual_p95 <= max_residual`（建议起始值 `0.03m~0.05m`）
8. 若 `cam_height_above_floor < 0.8m`（典型台面误检），必须继续扩大低分位重试，不得立即终止
9. 任一尝试通过则输出 `floor_status = OK`；并落盘 `ransac_low_height_quantile_used` 与 `ransac_attempts`
10. 所有尝试失败时必须区分并落盘：
   - `sampled_points < min_points`：`fail_reason=insufficient_depth_points`（不进入 RANSAC）
   - 进入 RANSAC 但无可用平面：`fail_reason=ransac_no_plane`
   - 阈值失败：`fail_reason` + `fail_reason_detail`（例如 `residual_p95=0.12 > max_residual=0.05`）

### 2.3 兜底路径：Ray-way（射线估计）
当主路径失败时，必须立即进入射线兜底（同帧内完成，不依赖 navmesh，也不要求开启动态 physics）：
- 先执行 **Raycast 自检（preflight）**，用于判定是否可走 `cast_ray` 分支：
  - 从 `AABB.center + (0, 2*extent_y, 0)` 向 `dir=(0,-1,0)` 发射长射线
  - 期望：`hit_count >= 1` 且首个命中距离合理（例如 `<100m`）
  - 自检结果必须落盘到 `ray_preflight`
- 若 `ray_preflight` 失败且运行环境不支持 `cast_ray`（例如无 bullet），允许切换 `depth-proxy` 兜底：
  - 在 world 中按 `ray_grid` 的 `x/z` 偏移，使用深度反投影点云近似“垂直射线命中”
  - 局部命中不足时，用低高度点做聚类并结合 `cam_height` 先验选主峰
  - 输出仍归一到同一套字段（`ray_hit_count / median / mad / floor_height`）
- 采样拓扑与尺度必须固定并落盘：
  - `ray_grid = 3x3`（或 `cross5`）
  - `ray_offset_m = 0.15`（相机局部 `x/z` 平面偏移，单位米）
- 所有 ray 起点在世界系中计算：
  - `p_origin = p_cam + up*0.05 + R_wc * [dx, 0, dz]^T`（`dx,dz` 来自网格偏移，`0.05m` 用于避免起点贴面）
  - ray 方向固定 `dir = -up`，并在代码里断言为世界系 `(0,-1,0)`
- 仅保留法线接近 `up` 的 hit（例如 `dot(n_hit, up) > 0.85`）
- 用中位数聚合 `floor_height`，并落盘：
  - `ray_hit_height_median`
  - `ray_hit_height_mad`（median absolute deviation）
  - 可选：`ray_hit_height_p95_minus_p50`
- 通过条件建议：
  - `ray_hit_count >= min_hits`（建议 `>= 5`，对应 `3x3` 的有效命中下限）
  - `ray_hit_height_mad <= 0.05m` 或 `ray_hit_height_p95_minus_p50 <= 0.08m`
  - `cam_height_above_floor ∈ [0.8m, 2.2m]`
- 若满足条件，输出 `floor_status = FALLBACK_OK`（`floor_method = ray_fallback` 或 `ray_fallback_depth_proxy`）
- 否则输出 `floor_status = FAIL` 并写入 `fail_reason` 与 `fail_reason_detail`

### 2.3b Floor 初始化视角（推荐开启）
- Step 2 可在估计 floor 的单帧上启用轻微俯视（只影响 Step2 初始化帧，不改 Step1 采样策略）
- 建议默认：`target_y = camera_y - 0.6m`（或等价 `pitch_down ≈ 10°~20°`）
- 目的：提高地面像素占比，减少“看墙导致 RANSAC 拟合竖直平面”
- 必须落盘：`floor_init_lookdown_applied` 与 `floor_init_lookdown_delta_y_m`

### 2.3c Pose 应用链路闭合（必须）
- Step2 估计必须基于 `before` 观测：
  - 先渲染并保存 `step2_floor_rgb_before.png`（可选同步 `depth_before`）
  - 用 `before.depth` 做 floor 估计，得到 `floor_height`
- 当 `floor_status in {OK, FALLBACK_OK, SLOPE_OK}`：
  - 计算 `target_cam_y = floor_height + sensor_height`
  - 仅调整 `camera_position.y`（保持 yaw / lookdown 规则），并写回 agent/sensor
- 应用后必须再渲染 `after`（兼容旧名）：
  - `step2_floor_rgb.png` 继续表示“应用后”
  - 记录 `floor_pose_apply_rgb_l1_diff` 作为链路自证
- 自动告警规则：
  - 若 `|cam_y_delta_floor_adjust| > 0.10m` 且 `rgb_l1_diff == 0`，追加 warning：`FLOOR_APPLY_CHAIN_BROKEN_SUSPECTED`

### 2.4 多帧稳定性（推荐：滤波但不隐藏原始值）
- 每帧都保留 `floor_plane_raw`（原始估计）
- 可选输出 `floor_plane_smooth`（EMA 或滑动窗口鲁棒拟合）
- 明确记录 `floor_used = raw | smooth`，Step 3 默认消费 `floor_used`
- 若平滑器尚未“热启动”（前几帧不足），`floor_used` 可暂时回退到 `raw`

### 2.5 Fail-fast 与跳帧策略
- 单帧 `floor_status = FAIL`：允许跳帧，但不得写入“有效轨迹帧”
- 连续失败超过阈值：`max_consecutive_floor_fail`（建议默认 `8`）即终止当前序列
- 序列级质量门限：
  - `floor_valid_ratio >= 0.85`
  - `fallback_ratio <= 0.30`（超过说明主路径退化）
- Step 3 仅消费 `floor_status in {OK, FALLBACK_OK}` 的帧

### 2.6 Step 2 的验收标准
- [ ] 绝大多数帧能稳定估计地面法线（方向一致）
- [ ] 相机高度分布合理且连续（无异常跳变）
- [ ] 明显桌面/床面不被误判为地面（由高度 + 残差 + 射线离散度共同约束）
- [ ] `floor_status` 与 `fail_reason` 完整落盘，无 silent fail

> 产物建议：每帧至少记录 `floor_status / floor_method / floor_plane_raw / floor_plane_smooth / floor_used / floor_confidence / cam_height_above_floor / cam_y_delta_floor_adjust / floor_pose_apply_applied / floor_pose_apply_rgb_l1_diff / ray_preflight / ransac_attempts / floor_init_lookdown_applied / fail_reason / fail_reason_detail`。  
> Step2 图像产物建议固定：`step2_floor_rgb_before.png`（应用前）+ `step2_floor_rgb.png`（应用后，兼容旧消费方），并在 `traj_meta.json` 聚合 `floor_valid_ratio / fallback_ratio / ray_height_unstable_ratio`。

### 2.7 可选增强（默认关闭，不影响基础验收）
- **第二平面复核**：主平面通过后，可在剩余点再拟合次大平面；若次平面同样满足 `normal_up` 且 `cam_height_above_floor` 更合理，可切换为次平面并记录 `floor_method = ransac_second_plane`
- **坡度分档**：默认 `dot(n, up) > 0.9` 才算 `OK`；可扩展为 `0.8 < dot(n, up) <= 0.9` 记为 `SLOPE_OK`，并在 `traj_meta.json` 统计 `slope_ok_ratio`
- **强制 RANSAC 调试**：仅用于对比实验，可开启 `step2_force_ransac_accept_debug=true`，将“有平面但阈值未过”的结果标记为 `floor_method=ransac_forced`（必须保留 `fail_reason_detail` 说明被强制通过）
- **应用链路自证**：调试时必须同时看 `cam_y_minus_floor_height` 与 `cam_y_delta_floor_adjust`；若 `|cam_y_delta_floor_adjust|` 明显非 0 但渲染图完全一致，则说明“floor 结果未被应用到渲染 pose”

## Step 3：连续性 + 覆盖保证（ExplorerFSM + MotionController）

> 目标：Step3 不再逐帧贪心，而是“上层状态机决定意图 + 底层控制器平滑执行”，同时解决抖动、小步长、拐角犹豫、覆盖不足。  
> 执行顺序强约束：**Step3 只在 Step1 通过（`step1_ok=true`）且 Step2 通过（`floor_status in {OK, FALLBACK_OK, SLOPE_OK}`）后启动**。  
> 原则：先安全，再覆盖；先可解释，再优化。

### 3.0 架构总览（必须）
- 上层 `ExplorerFSM`：决定“去哪、多久不改主意”，禁止每帧重规划
- 下层 `MotionController`：只负责按目标平滑走到位（转向/步长/clearance 限幅）
- 统一状态集合（仅 4 个）：
  - `WALL_FOLLOW`：沿墙稳定推进（单 room 最有效）
  - `ESCAPE_SCAN`：卡住时 360° 扫描，选新方向
  - `TURN_IN_PLACE`：大角度需求时先原地转到位
  - `COMMIT_RUN`：锁定 heading 连续推进一段距离/时长
- 状态切换优先级（必须写死）：
  - `Safety Override(黑帧/碰撞风险)` > `TURN_IN_PLACE` > `ESCAPE_SCAN` > `COMMIT_RUN` > `WALL_FOLLOW`
- `recovery_used` 语义（必须）：
  - recovery 是底层兜底动作，不直接改变上层 `fsm_state`
  - recovery 连续失败或超限后，才触发上层状态切换（通常转 `ESCAPE_SCAN`）

### 3.1 关键定义（统一口径）
- `pose_t = (p_t, q_t)`：世界系位置与姿态
- `Δp_t = ||p_t - p_{t-1}||`（米）
- `Δyaw_t`：相邻帧 yaw 变化（度）
- `Δh_t = |(cam_y_minus_floor_height)_t - (cam_y_minus_floor_height)_{t-1}|`（米）
  - 高度连续性统一使用 Step2 的 `cam_y_minus_floor_height`，禁止直接用 `p_t.y`
- `continuity_status = OK | RECOVERY_OK | FAIL`
- `motion_policy = wall_follow | escape_scan | turn_in_place | commit_run`
- `frontier_hits`：沿候选方向从 visited->unvisited 的边界穿越次数（或归一化计数）
- `visited_unique_cells`：访问过的唯一栅格数量
- `coverage_area_m2 = visited_unique_cells * grid_res_m^2`

### 3.2 输入 / 输出（落盘字段）
**输入（来自 Step1/2）**
- `accepted_pose`（Step1）
- `floor_status in {OK, FALLBACK_OK, SLOPE_OK}`（Step2）
- `cam_y_minus_floor_height`、`rgb/depth`

**每帧输出（`poses.jsonl`）**
- `continuity_status` / `continuity_fail_reason` / `continuity_fail_detail`
- `fsm_state` / `fsm_prev_state` / `fsm_state_frames`
- `delta_pos_m` / `delta_yaw_deg` / `delta_h_m`
- `clearance_fwd_m` / `clearance_left_m` / `clearance_right_m` / `clearance_fwd_left_m`
- `novelty_score` / `frontier_hits_norm` / `scan_score_best` / `scan_best_heading_deg`
- `scan_phase = rotate | nudge` / `scan_nudge_steps_used`
- `commit_frames_left` / `commit_dist_left_m`（决策以 `commit_dist_left_m` 为主）
- `recovery_used = none | rotate_probe_big | backoff | sidestep | reanchor`
- `collision_proxy = {near_wall_ratio, min_depth_m, forward_clearance_m}`
- `progress_marker` / `stage_timing_sec.t_step3_policy|render|write`

**序列输出（`traj_meta.json`）**
- `continuity_valid_ratio` / `recovery_ratio` / `collision_ratio`
- `max_consecutive_recovery` / `escape_scan_attempts_total` / `escape_scan_attempts_consecutive` / `escape_scan_success_ratio`
- `path_length_m` / `avg_step_m` / `net_displacement_m`
- `visited_unique_cells` / `coverage_area_m2`
- `fail_reason_histogram` / `run_state = DONE | FAIL | TIMEOUT`

> 规则：任何 FAIL 都必须写 terminal 记录（最后一帧或 terminal record），禁止 silent fail。  
> terminal record 必须包含：`last_fsm_state`、触发 gate 名称、stuck 窗口统计、scan/recovery 计数器值。

### 3.3 Visited Grid 与 Novelty（替代贪心）
- 在世界系 `XZ` 平面维护 visited 栅格：
  - `grid_res_m` 建议 `0.25~0.50`
  - 每帧 mark 当前 `(x,z)` 所在格
- `novelty(yaw)` 采样规则（必须）：
  - `sample_len = min(clearance(yaw), novelty_cap_m)`，建议 `novelty_cap_m = 3~5m`
  - 仅在有效可达长度内采样，禁止把深度孔洞/穿墙区域当 novelty
  - 采样间距建议 `0.25~0.50m`（与 grid_res 同级）
- `frontier_hits(yaw)`：
  - 沿方向射线统计 visited->unvisited 的边界穿越，得到 `frontier_hits_norm`
- `ESCAPE_SCAN` 打分统一公式：
  - `score(yaw) = clearance(yaw) * (1 + lambda1_novelty * novelty(yaw) + lambda2_frontier * frontier_hits_norm(yaw))`
  - 建议 `lambda1_novelty = 1.5~3.0`，`lambda2_frontier = 0.5~1.5`

### 3.4 状态机执行规则（核心）
1. `WALL_FOLLOW`（默认启动）
   - 左手贴墙默认：
     - `e = d_left - d_target`
     - `yaw_cmd = clamp(-k_p * e, -yaw_max, yaw_max)`
   - 增加墙角保护：若 `d_fwd_left < corner_block_thresh`（建议 `0.35m`），优先向右脱角或转 `TURN_IN_PLACE`
   - 仅在 `d_fwd > fwd_min` 且 `|yaw_err| <= turn_enter_deg` 时前进，否则转 `TURN_IN_PLACE` 或 `ESCAPE_SCAN`
2. `ESCAPE_SCAN`
   - 两段式（必须）：
     - `SCAN_ROTATE`：360° 离散扫描（建议 36 bins），按 `score(yaw)` 排序
     - `SCAN_NUDGE`：朝 top-1 heading 小步推进 `2~3` 步（每步 `0.15~0.25m`）后重评估
   - 若 nudge 后分数无提升，自动尝试 top-2 heading；多次失败才计一次 scan 失败
3. `TURN_IN_PLACE`
   - 当 `|yaw_error| > turn_enter_deg`（建议 25°）进入
   - 每帧允许较大转角（建议 12°~20°）直到 `|yaw_error| < turn_done_deg`（建议 8°）
   - **TURN_IN_PLACE 严禁 forward**（action=rotate only）
4. `COMMIT_RUN`
   - 锁 heading，连续走一段（决策以 `commit_dist_m` 为主，`commit_frames` 仅兜底）
   - 每帧按实际 `Δp_t` 扣减 `commit_dist_left_m`
   - commit 中禁止重规划；仅当安全条件崩坏（黑帧/clearance 急降/碰撞风险）允许中断到 `ESCAPE_SCAN`

### 3.5 连续性与安全硬约束（Gate）
- `Δh_t <= h_max`（建议 `0.08m`）
- `Δp_t` 按状态分层（必须）：
  - `WALL_FOLLOW`：`Δp_t <= 0.30m`
  - `COMMIT_RUN`：`Δp_t <= 0.40m`
  - `TURN_IN_PLACE`：`Δp_t <= 0.10m`
- yaw 约束按状态分层：
  - `WALL_FOLLOW / COMMIT_RUN`：`Δyaw_t <= 20°`
  - `TURN_IN_PLACE`：临时放宽到 `45°~60°`
- 任一 gate 失败：
  - 先转入恢复/扫描分支
  - 超过恢复上限后才 FAIL

### 3.6 卡死治理（Fail-fast 但不早杀）
- `near_wall_streak`、`forward_but_stuck`、`net_disp_window` 仅用于触发 `ESCAPE_SCAN`，**不直接判死**
- stuck 判定建议（滑窗 30 帧）：
  - 净位移 `< 0.25m` 或 路径长度 `< 0.60m`
  - 或 `near_wall_ratio` 连续超阈值
- `ESCAPE_SCAN` 冷却（必须）：
  - `escape_scan_cooldown_frames = 15~30`
  - 冷却期内禁止重复进入 `ESCAPE_SCAN`（除非 safety 崩坏）
- 失败升级链路：
  - `WALL_FOLLOW -> ESCAPE_SCAN -> TURN_IN_PLACE/COMMIT_RUN`
  - 仅 `escape_scan_attempts_consecutive > max_escape_attempts` 才 terminal fail

### 3.7 无 Navmesh 分支（No-Navmesh FSM）
- 无 navmesh 时仍跑同一 FSM，只替换几何来源：
  - clearance 来源：`depth-proxy`（禁止依赖 physics ray）
  - 预检来源：depth 中央扇区 + 侧向扇区
- depth-proxy 统计必须鲁棒：
  - `clearance_fwd = p30(depth_center_sector_valid)`
  - `min_depth_m = p5(depth_center_sector_valid)`（碰撞风险 proxy）
  - blank/depth holes 必须显式掩码，禁止把空洞当“超远可走”
- 步长策略（安全覆盖折中）：
  - `step_len = clamp(step_nominal, step_min, step_clearance_scale * clearance_fwd)`
  - 建议 `step_min >= 0.12m`，避免 micro-step 冻住
- 若连续无法推进：优先 `ESCAPE_SCAN`，再 `reanchor`（回 Step1），最后才 FAIL

### 3.8 运动量目标（覆盖不是靠帧数）
- 终止条件建议改为：
  - `frame_count >= target_frames` **或** `path_length_m >= path_target_m`
- 默认建议：
  - `target_frames = 80`
  - `path_target_m = 8.0`
- 序列质量门槛（建议）：
  - `avg_step_m >= 0.10`
  - `net_displacement_m >= 3.0`（可按场景调）
  - `visited_unique_cells >= N_min`（按场景尺度配置）
  - `coverage_area_m2` 不低于经验下限（按资产类型分桶）

### 3.9 调试产物（最小集）
- `poses.jsonl`
- `traj_meta.json`
- `step3_fail_snapshot.png`（失败帧）
- `step3_debug_strip.png`（每 10 帧拼图）
- 可选：`visited_map_debug.png`（栅格访问热力图）

### 3.10 验收标准（场景级）
- [ ] Step3 在 `step1_ok && step2_ok` 前提下可稳定启动，无 early-crash
- [ ] `continuity_valid_ratio >= 0.90`
- [ ] `recovery_ratio <= 0.25`
- [ ] `max_consecutive_recovery <= 3`
- [ ] `avg_step_m`、`path_length_m` 显著高于旧版贪心策略
- [ ] `visited_unique_cells` 与 `coverage_area_m2` 达标，无“局部来回磨”
- [ ] 失败原因可统计可追溯（`fail_reason_histogram` 完整）

### 3.11 建议的失败原因枚举
- `step1_start_missing`
- `step2_not_ok`
- `floor_height_missing`
- `escape_scan_failed`
- `no_novel_direction`
- `frontier_signal_missing`
- `commit_blocked`
- `no_navmesh_stuck`
- `blank_frame_streak`
- `continuity_gate_failed`
- `escape_scan_cooldown_locked`

> 设计真相：Step1 是主力，Step3 必须服从 Step1。  
> Step3 不再“每帧贪心”，而是“状态机先定意图，控制器再平滑执行”。
