## Step 0：GLB 导入后全局初始化检查（必须对所有 GLB 一视同仁）

### 0.1 目的
不同资产的坐标系、尺度、原点、朝向都可能乱七八糟。若不统一处理，后续的“进室内 / 找地面 / 连续移动”全都会变成玄学。
必须先执行 scene stats pass（可不渲染），扫描 `/Users/sota/code/3d_new/data/scenes/3d-assets` 得到数据分布，再做后续初始化策略。

scene stats pass 产物：
- `scene_stats.json`
  - `max_dim` 分布（`min/median/p95`）
  - `aabb_volume` 分布（`min/median/p95`）
  - 异常场景识别（例如 `max_dim < 1m` 或 `max_dim > 200m`）

### 0.2 必做的初始化动作（对每个导入 GLB 都执行）
- **AABB 计算（世界坐标）**
  - 获取场景的 Axis-Aligned Bounding Box：`center`, `size`
- **尺度归一（可选但强烈建议）**
  - 让场景最长边落在一个合理范围（例如 10~50m 级别，具体看你的数据分布）
- **平移到原点**
  - `scene_translation = -AABB.center`，让中心对齐到 `(0,0,0)`
- **高度基线对齐（可选）**
  - 让 AABB 的 `min_y` 对齐到 0（或你定义的“地面附近”高度）

### 0.3 Step 0 的验收标准（Fail-fast）
- [ ] 导入后能稳定拿到 `AABB.center/size`
- [ ] `size` 不出现极端异常（比如全 0、或大到离谱）
- [ ] 执行平移/缩放后，场景仍可渲染、无崩坏
- [ ] 任意一次导入，初始化输出都有日志（scene_id / scale / translation）
> 产物建议：`scene_init.json`（每个 scene 一份），记录 scale、translation、AABB 等，用于复现与排查。

### 0.4 Navmesh 失败必须显式状态化（禁止 silent fail）
必须输出并落盘：
- `navmesh_status = OK | RECOMPUTED_OK | FAIL`
- `navmesh_fail_reason`（从异常和日志关键字归类）
- `fallback_used = none | relaxed_navmesh | no_navmesh_sampling`

并写入 `scene_init.json`（必要时同步到 `traj_meta.json`）用于统计失败分布。

### 0.5 Navmesh 策略：检测 → 多级修复 → 兜底
1. 优先加载已有 navmesh（若存在缓存）：
   - 先检查 `pathfinder.is_loaded`
   - 命中缓存则直接加载，避免重复构建
2. 未命中或加载失败则重建，并采用分级重试（从严格到宽松）：
   - Attempt A：默认参数（`NavMeshSettings().set_defaults()`）
   - Attempt B：增大 voxel/cell（更粗网格），适当降低 agent 半径/高度
   - Attempt C：进一步放宽可行走参数（如 climb/slope，取决于可调字段）
3. 每次重试后都必须做有效性检查：
   - `pathfinder.is_loaded == True`
   - `get_random_navigable_point()` 返回可用点

### 0.6 Step 0 输出新增字段（用于后续分支执行）
- `navmesh_status`
- `navmesh_attempts = [{attempt_id, settings_summary, success, error}]`
  - `settings_summary` 至少包含：
    - `agent_radius`
    - `agent_height`
    - `cell_size` / `voxel_size`（按 Habitat API 可用字段落盘）
    - `attempt_wall_time_ms`
    - `navmesh_poly_count`（如果可获取，否则写 `null`）
- `fallback_plan = navmesh | no_navmesh_sampling`
- `scene_init_ok` 与失败原因（fail-fast 时必须可追溯）
- `debug_cam_pose`（固定可复现的 debug 相机位姿：`position/rotation/fov`）

### 0.7 Debug 渲染可比对要求
Step 0 的 debug RGB/Depth 需要可跨场景对齐比较：
- debug 相机位姿必须由 AABB 规则确定，禁止随机位姿
- 相机参数（分辨率/FOV）固定
- `debug_cam_pose` 必须写入 `scene_init.json`

### 0.8 常见 navmesh 失败根因（用于日志归类）
- 场景尺度异常（超大/超小）
- mesh 非闭合、碎片化或自交
- agent 参数不合适（半径/高度导致不可走）
- 缺少可碰撞几何（只有 render mesh）
- 坐标轴/up-axis 混乱导致“地面”推断错误

## Step 1：先“进入室内”——否则数据没价值

### 1.1 前置依赖（必须）
Step 1 只能消费 Step 0 已完成且可追溯的初始化结果：
- `scene_init_ok == true`
- `quarantine == false`
- 使用 Step 0 落盘的 `post_scene_source`（优先）或 `scene_path`
- 读取 Step 0 的 `navmesh_status/fallback_plan/debug_cam_pose/sensor_config` 作为启动参考

> 原则：Step 1 不是重新导入场景，而是在 Step 0 统一坐标和尺度之后做“可用起点搜索”。

### 1.2 室内判定升级：硬门 + 打分（不依赖语义）
对每个候选位姿渲染深度后，计算 6 个廉价特征：
- `r_valid`: 深度有效像素比例（默认 `isfinite(depth) && depth > znear`；不建议用固定 `depth_valid_max_m` 作为 validity gate）
- `r_near`: 近距离占比（`depth < D_near`）
- `r_far`: 远距离占比（`depth > D_far`）
- `r_edge`: 深度边缘占比（Sobel/Canny，建议在 depth 上做）
- `d05`: 深度 5% 分位数（替代 `min(depth)`，更抗噪）
- `depth_iqr`: 深度 IQR（`p75-p25`，衡量结构层次）

硬门（Gate）：
- `r_valid > T_valid`（建议 0.6~0.7）
- `d05 > T_wall`（建议 0.15~0.25m，过滤贴墙/贴脸）

软评分（Score）：
- `S = w1*r_near + w2*(1-r_far) + w3*r_edge + w4*norm(depth_iqr)`
- `norm(depth_iqr)` 建议做裁剪归一化，避免被极端值污染
- 启动点选择采用 top-K（不要“第一个过线就停”）

> 说明：`depth_valid_max_m` 可以保留为可选兼容开关（仅在特殊数据集启用），默认应关闭；空旷惩罚由 `r_far` 和 `score` 完成。

### 1.3 进入室内策略：1-step lookahead 局部贪心
每次仅在小动作集合中选下一步：
- `turn_left_small`
- `turn_right_small`
- `forward_small`
- `forward_medium`
- `back_small`（防贴墙死锁）

动作选择：
- 对每个动作做 1 步试探渲染（低分辨率 depth 即可）
- 计算试探后的 `S`
- 选 `S` 最大的动作执行

停止条件：
- 达到 `S >= S_min` 且通过 Gate
- 或达到 `max_actions_per_start` 后切换起点

### 1.4 No-Navmesh 启动：三关筛选（必须可运行）
当 `navmesh_status == FAIL` 或 `fallback_plan == no_navmesh_sampling`：
- 关 1（落地可靠性）：
  - 在 AABB 采样 `(x,z)`，从高处向下 raycast 得 `p_floor`
  - 要求 `dot(hit_normal, up) > 0.8`，避免命中墙面
- 关 2（局部 clearance）：
  - 在相机高度做四向短射线（0.3~0.5m）
  - 任意方向过近命中则 reject
- 关 2.5（可选，向前命中）：
  - 沿候选 yaw 方向发短射线（2~5m，允许多次 yaw 试探）
  - 全 miss 或命中过远则 reject（典型失败码：`REJ_FORWARD_MISS/REJ_FORWARD_TOO_FAR`）
- 关 3（室内评分）：
  - 对候选点 + yaw 计算 Gate + `S`
  - 选 top-K 进入动作搜索

退出上限（防卡死）：
- `max_start_samples`（建议 200）
- `max_no_nav_candidates`（建议 100~300）

### 1.5 Step 1 输出（结构化失败，便于调参）
每个 scene 产出 `step1_start_report.json`（或并入 `traj_meta`）：
- `start_candidates_total`
- `accepted_candidates`
- `best_score`
- `best_metrics = {r_valid, r_near, r_far, r_edge, d05, depth_iqr}`
- `chosen_start_pose`（position/rotation/yaw）
- `planner_trace`（动作序列、每步分数）
- `reject_histogram`：
  - `REJ_INVALID_DEPTH`
  - `REJ_TOO_CLOSE_WALL`
  - `REJ_TOO_OPEN`
  - `REJ_LOW_TEXTURE`
  - `REJ_SCORE_LOW`
  - `REJ_NO_FLOOR_HIT`
  - `REJ_CLEARANCE_FAIL`
  - `REJ_FORWARD_MISS`
  - `REJ_FORWARD_TOO_FAR`

### 1.6 Step 1 验收标准（避免“勉强室内”）
- [ ] 90%+ scene 的起始帧通过 Gate 且 `S >= S_min`
- [ ] 起始帧满足质量下限：`d05 > 0.2m`、`r_valid > 0.7`
- [ ] 不出现大比例黑帧/空白帧/贴墙帧
- [ ] 所有失败 scene 均有结构化 `reject_histogram` 与 `fail_reason`

> 原则：Step 1 目标不是“找到一个能动的位置”，而是“找到可持续产出高质量轨迹的启动位姿”。

## Step 2：Floor（确定“地面”）——高度、连续移动、质量过滤的共同地基

> 目标：在 **不依赖语义、不依赖 navmesh** 的前提下，为每个可用帧稳定输出 `floor_plane / floor_normal / floor_height`，并给出明确的 `floor_status` 与 `fail_reason`。  
> 推荐策略：**RANSAC 平面拟合为主**；失败时进入 **Ray-way（射线兜底）**；两者都失败则 fail-fast（或跳帧）。

### 2.0 关键定义（强制统一）
- `up = +Y`（若资产不是 +Y up，必须在 Step0 统一并落盘）
- `floor_plane = (n_x, n_y, n_z, d)`（世界系，`n·x + d = 0`，`||n||=1`）
- 法向朝向统一：若 `dot(n, up) < 0`，强制 `n=-n, d=-d`
- `floor_height = -d / n_y`（仅在 `n_y >= min_ny` 时有效，默认 `min_ny=0.7`）
- `cam_height_above_floor = n·p_cam + d`（单位米）

> 约束：`abs(||n||-1) < 1e-3` 必须断言；否则 `cam_height_above_floor` 与 residual 都不可信。

### 2.1 输入 / 输出与依赖门禁
前置依赖（硬门）：
- Step0：`scene_init_ok=true` 且坐标系已统一
- Step1：`step1_ok=true`，`chosen_start_pose` 可用，且 `scene_source` 可追溯

输入：
- `depth`（必须）
- `K` 或 `hfov+resolution`（必须）
- `T_wc`（camera->world，必须明确方向）
- `rgb`（可选，debug）

输出（`step2_floor_report.json` / `frame_meta`）：
- `floor_status = OK | FALLBACK_OK | FAIL`（可选扩展 `SLOPE_OK`）
- `floor_method = ransac | ray_fallback | ray_fallback_depth_proxy | none`
- `floor_plane / floor_normal / floor_height / cam_height_above_floor`
- `valid_points_in_roi / sampled_points / inlier_ratio / plane_residual_p50,p95`
- `inlier_coverage`（新增，防小平面欺骗）
- `ray_preflight / ray_hit_count / ray_hit_height_median / ray_hit_height_mad`
- `floor_pose_apply_*`（before/after 读回、RGB L1、depth shift）
- `transform_check`（新增，见 2.2）
- `floor_confidence / fail_reason / fail_reason_detail / run_state`

推荐新增失败码：
- `transform_inconsistent`
- `normal_ny_too_small`
- `inlier_coverage_low`
- `depth_policy_reject`（启用深度上限时）

### 2.2 变换与数值自检（强制）
在首次估计前必须执行：
1. `T_wc` 闭环自检  
   采样 20 个点 `x_c`，做 `x_c -> x_w -> x_c'`，要求  
   `median(||x_c-x_c'||) < 1e-3`（或与你数值精度一致）
2. 光轴一致性检查  
   `R_wc * [0,0,-1]` 与由中心像素反投影出的 world 射线方向余弦应接近 1（如 >0.95）
3. 法向单位化检查  
   RANSAC 输出平面后再次断言 `||n||≈1`

任一失败：`floor_status=FAIL`，`fail_reason=transform_inconsistent`。

### 2.3 深度有效性策略（避免大场景误杀）
- 默认有效深度定义：`isfinite(depth) && depth > znear`
- 默认 **不** 用固定 `depth_valid_max_m` 作为 validity gate
- 若必须启用上限，使用自适应：  
  `depth_valid_max_m = min(zfar, max(200, 1.5*scene_max_dim))`
- 将“是否空旷”交给 `r_far` / score，不要混入 `r_valid` 定义

### 2.4 主路径：RANSAC 平面拟合（Primary）
1. ROI：默认图像 `60%~95%` 高度区间
2. 有效点过滤与下采样：`max_points=5k~20k`，`min_points>=500`
3. 反投影到 camera 点云，再用 `T_wc` 转 world 点云
4. 低高度切片重试：`q ∈ {0.20, 0.35, 0.50, 1.00}`
5. 每次切片执行 RANSAC，输出 `n,d,inliers,residual`
6. 几何门限（全部满足才通过）：
   - `dot(n, up) >= min_normal_dot_up`（默认 0.9）
   - `n_y >= min_ny`（默认 0.7，防 `-d/n_y` 爆炸）
   - `inlier_ratio >= min_inlier_ratio`（默认 0.15）
   - `plane_residual_p95 <= max_residual`（默认 0.03~0.05m）
   - `cam_height_above_floor ∈ [0.8, 2.2]m`
   - `inlier_coverage >= min_inlier_coverage`（默认 0.15，新增强门）
7. 通过即 `floor_status=OK`；失败进入 Ray-way

> `inlier_coverage` 计算建议：将 ROI 划为粗网格（如 `40x22`），统计被内点覆盖的有效 cell 占比。

### 2.5 兜底路径：Ray-way（同帧完成）
触发条件：RANSAC 全部失败。

Ray preflight（必须基于相机局部，而非 AABB center）：
- 使用 `cross5` 起点：`p_cam + up*0.05 + R_wc*[dx,0,dz]`
- 每个起点向 `dir=-up` 发射长射线
- 记录 `preflight_hit_ratio`，要求 `>= ray_preflight_min_hit_ratio`（建议 0.4）

分支：
- `cast_ray` 可用且 preflight 通过：走 `ray_fallback`
- preflight 失败或无 physics ray：走 `ray_fallback_depth_proxy`

通过条件建议：
- `ray_hit_count >= min_hits`（3x3 默认至少 5）
- `ray_hit_height_mad <= 0.05m`（或 `p95-p50 <= 0.08m`）
- `cam_height_above_floor ∈ [0.8, 2.2]m`

### 2.6 Floor 初始化与 pose 应用链路闭合（强制）
- 估计基于 `before` 帧：先渲 `step2_floor_rgb_before.png` + `depth_before`
- 可选轻俯视（推荐开）：`lookdown 10°~20°` 或 `delta_y≈0.6m`
- 若 `floor_status in {OK, FALLBACK_OK, SLOPE_OK}`：
  - `target_cam_y = floor_height + sensor_height`
  - 仅调整相机 y，保持 yaw/pitch 策略
- 应用后渲 `step2_floor_rgb.png`（after）
- 必须落盘链路自证：
  - `floor_pose_apply_readback_before/after`
  - `floor_pose_apply_rgb_l1_diff`
  - `depth_after_vs_before_shift`（新增硬证据）
- 告警：
  - 若 `|cam_y_delta| > 0.10m` 且 `rgb_l1_diff == 0` 且 depth shift 近 0  
    -> `FLOOR_APPLY_CHAIN_BROKEN_SUSPECTED`

### 2.7 Fail-fast、跳帧与批量稳态
- 单帧 FAIL 可跳帧，但不可当有效轨迹帧
- 连续失败阈值：`max_consecutive_floor_fail=8`（建议）
- 序列门限：
  - `floor_valid_ratio >= 0.85`
  - `fallback_ratio <= 0.30`
- 批量执行必须支持子进程隔离并记录：
  - `run_state = DONE | FAIL | TIMEOUT | CRASH_NATIVE | SKIP`
  - `progress_marker / timeout_stage / worker_exit_code`

### 2.8 floor_confidence（默认公式）
- `clamp01(x) = min(1, max(0, x))`
- RANSAC：
  - `conf = clamp01(w1*inlier_ratio + w2*(1-residual_p95/max_residual) + w3*(1-|cam_h-h_mid|/h_span))`
  - 默认 `w1=0.4, w2=0.4, w3=0.2, h_mid=1.5, h_span=0.7`
- Ray：
  - `conf = clamp01(w1*(hit_count/expected_hits) + w2*(1-mad/0.05))`
  - 默认 `w1=0.6, w2=0.4`

### 2.9 Step2 验收标准（更新）
- [ ] `T_wc` 自检通过率 100%，无 `transform_inconsistent` 漏报
- [ ] 绝大多数有效帧 `floor_status in {OK, FALLBACK_OK}`，且法向方向一致
- [ ] `cam_height_above_floor` 分布稳定连续，无异常跳变
- [ ] 桌面/小平面误检可被 `inlier_coverage` 与高度门限拦截
- [ ] 所有 FAIL 有结构化 `fail_reason + fail_reason_detail`，无 silent fail

> 结论：Step2 的目标不是“拟合出任意平面”，而是“在坐标正确、链路可证、批量可运营的前提下输出可用于 Step3 的稳定地面估计”。

## Step 3：连续性 + 覆盖保证（ExplorerFSM + MotionController，Final v4 / tune5）

> 目标：连续性稳定（少抖、少卡死）、覆盖显著增长（不只在单房间打转）。  
> 核心：贴墙主导 + 开口穿越 + 覆盖停滞逃逸，且对黑帧/出界采用“软处理优先”策略。  
> 当前稳定基线：`git tag step3_tune5_ok`。

### 3.0 启动 Gate（强约束）
仅当以下条件全满足才允许 Step3 启动：
- `step1_ok == true` 且存在 `accepted_pose`
- `floor_status in {OK, FALLBACK_OK, SLOPE_OK}`
- `cam_y_minus_floor_height` 可用

否则 terminal FAIL（禁止 silent fail），terminal record 必含：
- `last_fsm_state`
- `gate_name`
- `fail_reason`
- `counters_snapshot`

### 3.1 状态机（4 状态）
- `WALL_FOLLOW`：默认巡航（左手贴墙）
- `TURN_IN_PLACE`：凹角/近障碍时原地转向（`step_cmd=0`）
- `ROOM_CHECK_COMMIT`：开口触发后锁定 heading 跨阈值推进
- `ESCAPE`：覆盖停滞时 scan+commit 逃逸

优先级（写死）：
- `Safety Override > TURN_IN_PLACE > ESCAPE > ROOM_CHECK_COMMIT > WALL_FOLLOW`

### 3.2 depth-proxy（统一几何来源）
每帧统计：
- `clearance_fwd_m = p30(center sector)`
- `clearance_left_m`, `clearance_right_m`, `clearance_fwd_left_m`
- `min_depth_m = p5(center sector)`
- `valid_ratio`
- `outside_proxy`

说明：
- depth holes/blank 必须显式 mask，空洞不算“超远可走”。
- `outside_proxy` 由 `valid_ratio + center/side valid ratio` 共同判定，不靠单一阈值。

### 3.3 凹角/开口判别（必须落盘）
输出字段：
- `geom_event = NONE | CORNER_INNER | OPENING_OUTER`
- `delta_l`, `delta_f`（短窗中位基线差）

默认判别参数（代码默认）：
- `CORNER_INNER`：`F<0.55 & FL<0.35` 或 `ΔF<-0.30 & FL<0.45` 或 `F<0.60 & near_wall_ratio高`
- `OPENING_OUTER` 投票：`ΔL>0.40`、`L>1.50`、`F>1.20`，`votes>=3` 且 `valid_ratio` 合格
- opening 需连续命中：`opening_persist_frames=3`
- opening 放行还需 `wall_lock=true`（最近 8 帧中至少 6 帧 `L in [0.25,1.2]`）

### 3.4 MotionController（按状态分层）
只信实际位移（`delta_pos_m`），commit 扣减也按实际位移。

步长默认：
- `WALL_FOLLOW`: `step_nominal=0.24`, `scale=0.40`
- `ROOM_CHECK_COMMIT`: `step_nominal=0.35`, `scale=0.50`
- `ESCAPE`: `step_nominal=0.30`, `scale=0.50`
- 通用：`step_min=0.14`, `step_max=0.45`, `step_obstacle_margin=0.15`
- anti-freeze：`F>1.0` 时保证 `step>=0.25`

yaw 限幅默认：
- `wall_yaw_limit_deg = 14`
- `turn_yaw_limit_deg = 14`
- `commit_yaw_limit_deg = 9`
- `escape_commit_yaw_limit_deg = 9`

### 3.5 安全与连续性 Gate
硬约束：
- `delta_h_m <= 0.08`
- `delta_pos_m` 按状态上限：
  - wall `<=0.30`
  - commit/escape `<=0.40`
  - turn `<=0.10`
- `delta_yaw_deg` 按状态上限：
  - wall/commit `<=20`
  - turn `<=60`

连续性超限处理：
- 先记 `RECOVERY_OK`，并转 `ESCAPE` 尝试恢复
- 连续恢复超限才 terminal FAIL（`continuity_gate_failed`）

### 3.6 黑帧/出界策略（tune5）
黑帧不再单独硬失败，采用软触发：
- `black_soft_alert = (black_void_ratio > 0.30) OR (black_ratio > 0.35 AND valid_ratio < 0.75)`
- `black_soft_streak` 仅触发保守恢复/逃逸，不直接 FAIL

硬失败来源保留：
- `blank_frame_streak`
- `depth_valid_ratio` 连续过低
- `outside_proxy` 连续命中

但对“已跑出有效路径”的场景执行软落地：
- 当 `depth/outside` 触发硬门时：
  - 若 `path_length_m >= path_min_done_m(12m)` 或 `>= hazard_soft_timeout_path_m(5m)`，转 `TIMEOUT`
  - 否则 `FAIL`

### 3.7 ESCAPE 卡死治理（tune5 关键）
- 进入 `ESCAPE` 时记录最近有效移动方向为“禁回头扇区”
- scan 时默认排除禁区方向（`no_back_forbid_half_deg=35`, `no_back_forbid_frames=40`）
- 若 `ESCAPE commit` 连续零位移达到 `escape_blocked_rescan_streak=8`：
  - 立即清空当前 heading lock
  - 更新禁回头方向
  - 触发下一轮重扫（避免同方向死循环）
- `max_escape_attempts = 6`

### 3.8 启动保护与脱墙节制
- 启动保护窗：
  - `startup_wall_guard_active = (frame_idx < 15) AND (path_length < 2.0m)`
  - 保护窗内不允许常规 ROOM_CHECK/ESCAPE（安全例外除外）
- 保持 wall-follow 主导，但不禁用后续探索

### 3.9 终止条件（代码口径）
DONE：
- `path_length_m >= path_max_m(55)`，或
- `path_length_m >= path_min_done_m(12)` 且 `coverage_plateau=true`

TIMEOUT：
- 达到 `target_frames(220)` 且 `path_length_m >= 12`
- 或触发 hazard 软落地（见 3.6）

FAIL：
- 达到 `target_frames` 但 `path_length_m < 12`
- 或早期硬门失败且未达到软落地路径阈值

### 3.10 落盘字段（新增对齐）
